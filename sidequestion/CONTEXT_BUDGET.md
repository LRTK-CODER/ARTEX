# 별도 질문의 긴 대화와 컨텍스트 예산

2026-09-11에 고쳤다. 원래 구현은 요청 JSON의 글자 수를 그대로 토큰 수로 보고 메인 작업의 32K 출력 예약을 이어받았다. 그래서 HTML, JS, 도구 결과가 많으면 정상적인 별도 질문을 너무 일찍 거부했다.

## 오픈 소스 구현 확인

- [Grok CLI 별도 질문 컨텍스트](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/agent.ts#L739): 최근 사용자·어시스턴트 텍스트에서 조각을 뽑는다. 글자 예산은 약 2000자이고 한 건에서 최대 400자를 자른다. 이 경로에서는 이어지는 별도 질문·답변 기록을 유지하지 않는다.
- [Grok CLI 별도 요청](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/utils/side-question.ts): 따로 두는 취소 신호. 모델이 지원하면 출력 최대 2048 토큰. 도구를 주지 않는다.
- [Grok CLI 메인 세션 압축](https://github.com/superagent-ai/grok-cli/blob/fb97af83f06dca873281d60168430f06c8de6324/src/agent/compaction.ts): 토큰을 추정하고, 최근 내용을 남기고, 새 내용을 이전 요약에 반영하며, 턴에 걸친 잘림을 처리한다.
- [OpenCode 세션 압축](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/compaction.ts): 전체 요청 추정, 출력·버퍼 예약, 최근 내용 + 롤링 요약, 도구 없는 요약 요청. 이 구현의 기본값은 최근 내용 예산 8000, 요약 출력 최대 4096 토큰이다.
- [OpenCode 오버플로 복구](https://github.com/anomalyco/opencode/blob/b3f1a96c6dd7adeb28b36dd11add1998fc84d67b/packages/core/src/session/runner/llm.ts): 어시스턴트 출력이 아직 시작되지 않았을 때만 오버플로 복구를 시도하고, 복구한 뒤의 호출은 같은 오버플로 복구 경로로 다시 들어가지 않는다.

ARTEX는 따로 두는 출력 예산, 최근 내용과 롤링 요약, 횟수가 제한된 복구 방식을 가져왔다. norma v0.3.6의 구조화 메시지와 도구 호출·결과 짝은 유지하고, Grok의 텍스트 발췌 방식은 그대로 따르지 않는다. OpenCode의 메인 세션 압축 이벤트를 ARTEX 메인 transcript에 쓰지 않는다.

## 요청 예산과 실행

- 메시지는 norma의 콘텐츠 블록별 UTF-8 바이트 추정과 4/3 여유를 그대로 쓴다. 여기에 시스템 프롬프트, 도구 schema, 메시지 포장 비용을 더 센다. 추정값은 모델의 정확한 토큰 수가 아니다.
- 별도 질문 출력은 기본 최대 8192 토큰이고, 메인 설정에 정한 출력 최대값도 넘지 않는다. 서비스 환경 변수 `ARTEX_BTW_MAX_OUTPUT_TOKENS`로 256–32768 사이의 최대값을 정할 수 있다. 제품 기본 모델이나 메인 작업 파라미터는 바꾸지 않는다.
- 입력 예산은 컨텍스트 창에서 출력 최대값과 안전 여유를 뺀 값이다. 창 크기를 모르면 플랫폼 기본값 200K를 쓴다. 안전 여유는 창의 5%이고, 최소 128, 최대 8192 토큰이다.
- 성공한 질문·답변은 순번이 늘어나는 순서로 한 번에 최대 20쌍씩 불러온다. 원문은 최대 20쌍을 남기고, 그 토큰 예산은 입력 예산의 1/4 이하이면서 16K를 넘지 않는다.
- 넘친 질문·답변은 롤링 요약에 반영한다. 요약에는 기록 출처와 컨텍스트 시각이 붙는다. 이전 어시스턴트 답변은 새로운 도구 증거와 같지 않으므로, 서로 어긋나면 최신 메인 스냅숏을 우선한다.
- 메인 컨텍스트가 여전히 너무 길면 사본의 오래된 메시지만 요약하고, 최근 내용은 최대 8K 토큰을 남긴다. 자르는 지점은 도구 호출과 결과를 떼어 놓지 않는다. 너무 큰 한 쌍은 통째로 요약에 들어간다.
- 요약 입력은 실제 남은 창에 맞춰 UTF-8을 깨뜨리지 않게 나눈다. 출력 최대는 2048 토큰이다. 빈 요약, 잘린 요약, 도구 호출, 요약 예산 초과는 캐시에 쓰지 않는다. 별도 질문 한 건에서 요약 호출은 최대 12회이고 같은 120초 시간 제한을 따른다. 한도에 닿으면 무한 반복하지 않고 명확히 실패한다.
- 모델이 첫 응답에서 컨텍스트 한도 초과를 돌려주고 아직 텍스트나 도구 호출을 출력하지 않았다면, 더 줄여서 최대 한 번 재시도한다. 추정 크기가 줄지 않으면 복구를 바로 멈춘다. 다른 모델 오류나 일부만 받은 스트리밍 출력은 이 복구를 실행하지 않는다.
- 요약, 실패한 시도, 취소 시점까지 얻은 사용량을 모두 같은 별도 질문 요청에 더한다. 제공자가 사용량을 돌려주지 않으면 0만 기록할 수 있고, 추정값을 실제 사용량처럼 꾸미지 않는다.

## 저장과 화면

`side_question_sessions.memory`는 이전 질문·답변 요약, 그 요약이 덮는 ordinal, 스냅숏 식별 정보별로 캐시한 메인 컨텍스트 요약을 저장한다. `side_question_requests.context_info`는 준비 단계, 실제로 다시 넣은 쌍 수, 요약 사용 상황, 예산 추정값을 저장한다.

요약은 원래 요청이 아직 실행 중이고 정리 버전이 일치할 때만 저장한다. 비우기는 캐시도 함께 지우므로 늦게 온 쓰기가 정리된 데이터를 되살리지 못한다. 새 스냅숏은 이전 스냅숏의 요약을 다시 쓰지 않는다. 요약 필드는 v3 작업 보관에 함께 저장한다. 이 필드가 없는 이전 v3를 복원할 때는 빈 객체로 채우고, v1/v2도 계속 읽을 수 있다.

POST는 요청을 먼저 받아들여 돌려주고, 준비와 압축은 백그라운드에서 한다. 이때 접수 잠금이나 데이터베이스 트랜잭션을 잡지 않는다. SSE와 기록은 준비, 질문·답변 정리, 사본 압축, 답변 단계를 보여 준다. 압축에 실패하면 그 별도 질문 요청의 실패 종료 상태로 저장한다. 프런트엔드는 오류를 남겨 두고 이번에 실패한 질문을 초안으로 되살리며, 떠 있는 알림으로 입력 칸을 가리지 않는다. 기록 폴링이 제출 오류를 더 이상 지우지 않는다.
