# 코딩 스타일 규칙

코드를 쓰거나 고칠 때 따른다. 어떤 언어로 쓰든 지킬 원칙만 적는다. 언어별로 지키는 방법은 언어별 문서(Go는 `go-style.md`, 프런트엔드는 `typescript-style.md`)에 있다. 설계 판단은 `architecture.md`를 따른다.

## 이름

- 업무 의미가 드러나게 짓는다. 타입을 이름에 넣지 않는다(`id_to_name_dict` 대신 `names_by_id`).
- 불리언은 질문형으로 쓴다: `is_active`, `has_owner`, `can_retry`. `flag`, `deleted` 같은 이름은 쓰지 않는다.
- 컬렉션은 복수형으로 쓴다: `usr_lst`가 아니라 `users`.
- 약어는 널리 쓰이는 것(`id`, `url`, `http`)만 쓴다. 같은 개념에는 저장소 전체에서 같은 영어 단어를 쓴다.
- 시간·크기처럼 단위가 중요한 값은 이름에 단위를 드러낸다: `timeout`이 아니라 `timeout_seconds`, `max_size_bytes`.

## 주석

- 주석은 한국어로 쓴다.
- "무엇"이 아니라 "왜"를 쓴다. 코드를 읽으면 알 수 있는 것은 적지 않는다.
  - 나쁜 예: `retries += 1  # retries를 1 늘린다`
  - 좋은 예: `retries += 1  # 첫 시도는 재시도로 세지 않으므로 여기서 센다`
- 코드와 맞지 않게 된 주석은 코드와 함께 고친다.
- 주석 처리한 코드는 남기지 않는다. 이력은 git에 있다.
- TODO는 `TODO: #<이슈 번호> - <설명>` 형식으로 쓴다. 이름 대신 이슈를 단다.

## 함수

- 깊은 중첩은 조기 반환으로 편다.

## 오류 처리

- 실패를 빈 값(`None`, 빈 목록, 기본값)으로 바꿔 정상 결과처럼 돌려주지 않는다. 호출자가 "결과가 없다"와 "계산하지 못했다"를 구분할 수 있어야 한다. 구분할 수 없으면 오류로 올린다.
- 처리할 수 있는 곳에서만 잡는다. 처리할 수 없으면 잡지 말고 올려 보낸다.
- 구체적인 오류만 잡는다. 잡는 범위는 짧게 둔다.
- 삼키지 않는다. 격리 지점(작업 루프 최상단 등)에서 어쩔 수 없이 멈추게 할 때는 기록하고 이유를 주석으로 단다.
- 다른 오류로 바꿔 올릴 때는 원인을 잇는다.

## 자원과 값 표현

- 연 것(파일, 연결, 프로세스)은 닫는다. 오류가 나도 닫히게 쓴다(Go는 `defer`로 닫는다).
- 외부 호출(네트워크, 하위 프로세스)에는 타임아웃을 둔다.
- 상태와 종류는 문자열 리터럴 대신 열거형으로 나타낸다.
- 의미 있는 숫자는 이름 있는 상수로 둔다(`MAX_RETRIES = 3`).

## 억제 주석

- 검사 억제 주석에는 규칙 코드와 이유를 붙인다. 코드 없는 억제는 쓰지 않는다.
- 억제하기 전에 코드를 고칠 수 있는지 먼저 본다.
