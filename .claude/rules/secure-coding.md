# 안전한 코드 작성 규칙

LLM, 외부 도구, 분석 대상을 다루는 코드를 쓰거나 리뷰하기 전에 읽는다. ARTEX는 **공격자가 통제하는 대상**(대상의 HTTP 응답, 가로챈 트래픽, 대상 파일)을 분석해 그 내용을 LLM에 넣고, **LLM이 스스로 도구를 골라 명령을 실행**한다. 계층과 경계의 정본은 `architecture.md`다. 여기서는 옮겨 적지 않고 가리킨다.

`.claude/` 아래 스크립트에는 적용하지 않는다.

등급: **규칙**은 어기면 결함이 될 가능성이 높고 테스트나 리뷰로 지켰는지 판정할 수 있는 것이다. 나머지는 **권고**다. ARTEX에는 Go 보안 린터가 없으므로 대부분의 확인 방법은 테스트와 리뷰다.

## 전제

프롬프트 주입을 확실히 막는 방법은 알려져 있지 않다. 프롬프트 주입은 분석 대상 안의 글이 LLM에 대한 지시처럼 읽혀 동작을 바꾸는 공격이다. ARTEX는 LLM이 도구를 실행하는 것이 설계라서, 막기보다 피해를 제한하는 쪽으로 짓는다.

| 규칙 | 등급 | 확인 방법 |
|---|---|---|
| 주입은 성공한다고 가정하고 피해를 제한하도록 설계한다. 프롬프트 기법과 모델의 방어는 보조 수단이다. | 권고 | 리뷰 |

## 신뢰하지 않는 입력과 LLM 출력

| 규칙 | 등급 | 확인 방법 |
|---|---|---|
| 분석 대상의 응답·본문·주석·파일 이름, 가로챈 트래픽, 외부 도구의 출력은 신뢰하지 않는 입력이다. LLM 출력도 신뢰하지 않는다. | 권고(정의) | 리뷰 |
| 신뢰하지 않는 입력을 system 프롬프트나 지시문에 지시로 넣지 않는다. 대상 데이터는 "자료"로 구분해 넣는다. | 규칙 | 테스트: 조립한 요청의 system·지시문에 대상 문자열이 지시로 섞이지 않는다 |
| 도구 호출의 허용·차단은 코드가 정한다. ARTEX는 모든 도구 호출을 실행 전에 guard PreToolUse 훅(`guard`)으로 거르고, 허용 여부는 DB의 가로채기 규칙(`intercept`)으로 정한다. LLM이 규칙을 바꾸게 하지 않는다. | 규칙 | 테스트: 도구 호출이 guard를 지나고, 차단 규칙에 걸리는 호출이 막힌다 |
| LLM이 고른 경로·식별자·대상은 코드에서 다시 검증한다. 있는지, 허용 범위(대상 루트·허용 호스트) 안인지 본다. | 규칙 | 테스트: 범위 밖 경로·호스트를 거부한다 |
| 도구 호출 중 패닉은 격리 지점에서 `recover`로 가둔다. 한 도구가 죽어도 에이전트 루프가 멈추지 않게 한다. | 규칙 | 테스트: 패닉하는 가짜 도구를 호출해도 루프가 계속된다 |

## 외부로 보내는 원문과 기록

ARTEX는 트래픽을 일부러 가리지 않고 통째로 저장하고(`traffic`), LLM 요청·응답 전문을 PG에 기록한다(`llmrec`). 그래서 이 데이터의 통제는 "자르기"가 아니라 "접근·보관"이다.

| 규칙 | 등급 | 확인 방법 |
|---|---|---|
| 트래픽 저장소와 LLM 기록은 민감 데이터로 다룬다. 이 저장소를 밖으로(새 로그 싱크, 외부 전송) 복제하거나 노출하는 경로를 추가하지 않는다. | 규칙 | 리뷰 |
| LLM·판단 요청에 비밀값(ARTEX 자신의 키·토큰, DB 자격 증명)을 싣지 않는다. 대상 데이터만 싣는다. | 규칙 | 테스트: 조립한 요청 본문에 가짜 비밀값이 없다 |

## LLM이 도구를 실행할 때

| 규칙 | 등급 | 확인 방법 |
|---|---|---|
| LLM이 준 값으로 셸 명령·질의·경로를 문자열로 이어 붙이지 않는다. 명령에 넣을 때는 셸 인용(`shellQuote` 같은 작은따옴표 이스케이프)으로 감싼다. | 규칙 | 테스트: 특수문자·공백·따옴표가 든 LLM 값이 인용돼 한 인자로 들어간다 |
| DB 질의는 자리표(`$1`)로 파라미터화한다. 신뢰하지 않는 값으로 질의문을 조립하지 않는다. | 규칙 | 리뷰, 테스트: 따옴표가 든 입력이 질의를 바꾸지 않는다 |
| 에이전트가 쓰는 도구는 읽기/정찰 위주로 두고, 파일 쓰기·임의 네트워크 같은 위험한 도구는 가로채기 규칙으로 통제한다. 새 도구를 줄 때 guard를 지나는지 본다. | 규칙 | 테스트: 등록한 도구가 guard 경로를 지난다 |

## 외부 도구 실행(Go)

대부분의 명령 실행은 `norma`의 Bash 도구를 지나고, 타임아웃·보안 기준선·프록시 환경 변수·출력 상한은 `norma`가 맡는다(`architecture.md` "외부 도구와 프로세스"). ARTEX Go에서 직접 `os/exec`를 쓸 때만 아래를 지킨다.

| 규칙 | 등급 | 확인 방법 |
|---|---|---|
| `os/exec`는 `exec.CommandContext`로 만들고 타임아웃을 `context`로 둔다. 무기한 실행을 두지 않는다. | 규칙 | 테스트: 시간 초과 시 context가 프로세스를 끊는다 |
| 인자는 리스트로 넘긴다. `sh -c "<보간한 문자열>"`처럼 셸을 거쳐 신뢰하지 않는 값을 넣지 않는다. | 규칙 | 리뷰, 어댑터 인자 테스트 |
| 자식 프로세스 환경 변수는 허용 목록으로 넘기고 ARTEX의 비밀값 변수(API 키, DB 자격 증명)는 넘기지 않는다. 이 방어는 도구가 대상 코드를 실행하지 않을 때만 유효하다. | 규칙 | 테스트: 가짜 비밀값이 자식 환경에 없고 필요한 변수는 있다 |
| 대상에서 온 파일 이름·인자는 `--` 뒤에 두거나 절대 경로로 바꿔 넘긴다. `-`로 시작하는 이름이 옵션으로 읽히지 않게 한다. | 규칙 | 테스트: `-`로 시작하는 파일 이름 |
| 종료 코드 오류·타임아웃·파싱 실패를 빈 결과로 바꾸지 않는다. "계산하지 못함"이나 오류로 올린다. | 규칙 | 실패 경로 테스트 |

## 역직렬화와 파싱

| 규칙 | 등급 | 확인 방법 |
|---|---|---|
| 분석 대상·도구 출력·LLM 출력은 `encoding/json`이나 안전한 YAML 파서로 읽는다. 임의 역직렬화(`gob` 등)에 신뢰하지 않는 입력을 넣지 않는다. | 규칙 | 리뷰 |
| 신뢰하지 않는 입력으로 정규식을 만들지 않는다. 큰 입력에 정규식을 돌릴 때는 입력 크기에 상한을 둔다(Go `regexp`은 선형이지만 입력이 크면 비용이 든다). | 권고 | 리뷰 |

## 분석 대상과 경로

| 규칙 | 등급 | 확인 방법 |
|---|---|---|
| 대상 작업 디렉터리는 저장소 밖 전용 디렉터리(`os.MkdirTemp`)에 둔다. | 규칙 | 테스트: 작업 디렉터리가 저장소 루트 밖이다 |
| 대상 안의 경로는 `filepath.Clean` 뒤 심볼릭 링크를 `filepath.EvalSymlinks`로 풀고 루트 포함 여부를 검사한다. 문자열 접두 비교만으로 검사하지 않는다. | 규칙 | 테스트: `../`, 절대 경로, 밖을 가리키는 symlink, 없는 파일 |

## 설정과 비밀값

ARTEX의 비밀값: DB 비밀번호/DSN, LLM API 키, 알림 채널 자격 증명.

| 규칙 | 등급 | 확인 방법 |
|---|---|---|
| DB DSN을 로그·오류·출력에 낼 때는 비밀번호를 가린다(`config.Redact`). | 규칙 | 테스트: 가짜 비밀번호가 출력에 `****`로만 보인다 |
| LLM 키는 UI·목록 응답에 싣지 않는다. 직렬화에서 빼고(`json:"-"`) 힌트(끝 몇 글자)만 보인다. 목록 질의는 키 열(`api_key`)이 아니라 힌트 열(`api_key_hint`)을 읽는다. 키 전체는 실제로 제공자를 만들 단건 조회에서만 읽는다. | 규칙 | 테스트: 가짜 키가 목록·UI 응답 어디에도 없다 |
| 알림 채널 자격 증명은 마스킹 체계(`notify/mask.go`: `__masked__` 센티넬, 끝 몇 글자만 보임, 센티넬 재제출 거부)를 지난다. 웹훅 URL은 오류 메시지에서 가린다(`redactRequestTarget`). | 규칙 | 테스트: 가짜 자격 증명이 응답·오류에 원문으로 없다 |
| 비밀값과 분석 대상 원문을 일반 로그에 그대로 싣지 않는다(의도된 `traffic`·`llmrec` 저장소는 제외). 위치와 해시를 남긴다. | 규칙 | 리뷰 |
| 설정 검증 오류에 입력값을 넣지 않는다. 키 경로와 이유만 남긴다. | 규칙 | 실패 경로 테스트 |
| 비밀값을 커밋하지 않는다. 환경 변수(`ARTEX_PG_DSN`, `ANTHROPIC_API_KEY` 등)나 앱 안 설정으로 넣는다. 정본은 `AGENTS.md` "꼭 지킬 것". | 규칙 | 리뷰 |
| 비밀값을 담는 파일을 새로 만들면 소유자만 읽게(0600) 쓰고, 쓰는 도중 실패해도 기존 파일이 깨지지 않게 임시 파일에 쓴 뒤 이름을 바꾼다. | 규칙 | 테스트: 만든 파일의 권한, 쓰기 도중 실패 시 기존 파일 보존 |

## 외부 Go 모듈

`go.sum`과 checksum DB(sum.golang.org)는 이미 받은 버전의 바이트가 바뀌지 않음을 보장한다. 새 버전에 들어온 코드가 안전한지는 보장하지 않는다. 그래서 위험 지점은 버전을 올리는 순간이다.

| 규칙 | 등급 | 확인 방법 |
|---|---|---|
| 외부 Go 모듈, 특히 `github.com/Autumn-27/norma`의 버전을 올리는 PR은 이전 버전과의 소스 diff 요약(네트워크·파일·프로세스 실행 변경 중심)을 PR 본문에 적는다. | 규칙 | 리뷰: `go.mod` 버전 변경 PR 본문에 diff 요약이 있다 |
| `GOSUMDB=off`·`GONOSUMDB`·`GOFLAGS=-insecure`를 쓰지 않는다. 빌드 스크립트·워크플로·문서에 넣지 않는다. | 규칙 | 리뷰, `grep -rn 'GOSUMDB=off\|GONOSUMDB\|-insecure'` 결과가 이 문서뿐이다 |
